System design

Warehouse Watch, inside the portfolio

One Vercel deployment serves both the portfolio and the tracker. Serverless functions hold no state — every request pulls from Neon, talks to Costco's public endpoints directly, and the only long-running "process" is a free external scheduler pinging one route.

Life of a request — checking a watch's stock

  1. You open /costco; Vercel serves the SSR'd page from the same deployment as the portfolio.
  2. The UI calls POST /api/costco/items/:id/stock with your signed session cookie.
  3. The function loads the item's child id from Neon, then fans out to Costco's pickup endpoint once per tracked warehouse.
  4. Results are written back to Neon (warehouse_items) and returned; the UI renders in-stock / low / out per warehouse.

Life of an alert — back-in-stock push

  1. cron-job.org fires GET /api/costco/poll every 10 minutes with the CRON_SECRET header.
  2. The poll function reads all watches from Neon and re-checks each one against Costco (online stock or per-warehouse, per the watch's scope).
  3. It diffs against the last-known state stored in Neon — only an out → in transition counts.
  4. On a transition it POSTs to your private ntfy topic; the ntfy app pushes it to your phone. Web Push slots in beside this once the domain serves it.

Config is five env vars: DATABASE_URL · APP_PASSWORD · SESSION_SECRET · NTFY_TOPIC · CRON_SECRET.
